# Auth V1 로컬 검증

이 모듈은 실제 MySQL에서 Flyway와 제약 조건을 확인하는 스모크 테스트다. 인증 서비스, 운영 백업 또는 CI 설정을 포함하지 않는다.

## 재실행

JDK 17 이상, Maven과 임시 MySQL 8.4가 필요하다. `127.0.0.1`에만 연결 가능한 테스트 인스턴스에 이름이 `pm_auth_smoke_<12자리 소문자 16진수>`인 **새 빈 스키마**를 먼저 만든다. 이 모듈은 해당 이름 형식이 아니거나 비어 있지 않은 스키마에 쓰지 않는다. 운영 또는 기존 개발 데이터는 사용하지 않는다.

이 디렉터리에서 PowerShell을 연다. 예시의 포트·스키마·계정명을 테스트 인스턴스에 맞게 바꾸고 비밀번호가 필요하면 테스트용 환경에서 `PM_AUTH_DB_PASSWORD`를 주입한다.

```powershell
$env:PM_AUTH_JDBC_URL = 'jdbc:mysql://127.0.0.1:3307/pm_auth_smoke_0123456789ab'
$env:PM_AUTH_DB_USER = 'auth_smoke'
$env:PM_AUTH_MIGRATIONS = (Resolve-Path ../db/migration).Path
$build = Join-Path $env:TEMP ('pm-auth-smoke-' + [guid]::NewGuid().ToString('N'))
mvn "-Dpm.auth.build=$build" compile exec:java
```

검증 모듈은 테스트 데이터를 남기고 스키마를 삭제하지 않는다. 다음에 또 실행할 때는 빈 스키마를 새로 만든다.

## 확인 범위

| 검증 | 성공 조건 |
| --- | --- |
| Flyway | V1 최초 적용 1건, Auth 테이블 10개, 마이그레이션 검증 통과, 같은 스키마에서 재실행 시 적용 0건 |
| 번호 중복 가입 | 독립 DB 트랜잭션 두 개가 같은 번호 지문을 바인딩하려고 할 때 한 건만 커밋. 실패한 트랜잭션의 임시 회원 행도 롤백 |
| 소셜 계정·재인증 | 같은 제공자·앱 범위·식별자 중복 거부, 다른 제공자는 같은 회원에 추가 가능. 없는 회원 참조 거부, 필요한 재인증 기록 없이는 연동 확정 대기 상태로 변경 불가 |
| 가입 증표·OAuth 상태 | 흐름·번호 입력 버전당 증표 중복 거부, 검증되지 않은 증표 소모 거부, 번호 입력 버전 없는 연동 재인증 시도 거부, 같은 OAuth 상태의 재수락 거부 |

2026-11-23 Windows 로컬의 임시 MySQL 8.4.13과 Flyway 11.20.3에서 위 검증을 모두 통과했다. 테스트 뒤 임시 MySQL 프로세스를 종료했다.

카카오 실제 로그인, OCTOMO 문자 확인, 브라우저 쿠키·토큰, 계정 상태별 API 권한과 상태 전이는 서비스 구현 후 별도로 검증한다.
